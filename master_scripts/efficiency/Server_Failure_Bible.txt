
SERVER FAILURE BIBLE
Why Servers Fail Б─╒ How They Fail Б─╒ How People Fix Them Б─╒ Tools & Playbooks
(Windows 11 / Linux / Node / Python / WebSockets / Localhost stacks)

====================================================================
0) WHAT Б─°SERVER FAILБ─² REALLY MEANS
====================================================================
A Б─°serverБ─² fails when any of these break:
Б─╒ The process doesnБ─≥t start
Б─╒ The process starts but exits (crash)
Б─╒ The process runs but doesnБ─≥t accept connections (bind/listen failure)
Б─╒ It accepts connections but requests fail (runtime errors)
Б─╒ It works briefly then degrades (resource leak, deadlock, saturation)
Б─╒ ItБ─≥s healthy but unreachable (network/DNS/firewall/proxy)
Б─╒ ItБ─≥s reachable but wrong (misrouting, wrong port, wrong env, wrong version)

In practice, most Б─°mystery failuresБ─² are one of:
1) Dependency / environment mismatch
2) Permission / filesystem / path issues
3) Port binding conflicts
4) Network / proxy / firewall / TLS
5) Resource exhaustion (CPU/RAM/DISK/handles)
6) Concurrency bugs (deadlock, race)
7) Observability gaps (no logs / wrong logs / encoding)

====================================================================
1) THE UNIVERSAL FAILURE CHAIN (MENTAL MODEL)
====================================================================
Think in layers, always in this order:

L1: OS & Hardware
  - power, disk, RAM, CPU, drivers, clock, file system integrity

L2: Process & Runtime
  - interpreter/runtime exists, correct version, can execute, env vars set

L3: Config & Secrets
  - config file loads, JSON/YAML valid, keys present, permissions correct

L4: Dependencies
  - packages installed, native libs present, PATH correct, certs present

L5: Bind & Listen
  - port free, IP correct (127.0.0.1 vs 0.0.0.0), privileges ok

L6: Request Handling
  - routes, auth, DB connections, thread/async loop health

L7: External Integrations
  - DB, cache, message queue, web APIs, model endpoints, webhooks

L8: Observability
  - logging/metrics/traces, crash dumps, event logs

Fixing servers fast is mostly: identify which layer youБ─≥re stuck at.

====================================================================
2) STARTUP FAILURES (PROCESS NEVER STARTS)
====================================================================
2.1 Missing runtime
Б─╒ Python not found, Node not installed, wrong version
Fixes people try:
- Install correct runtime (winget/choco/installer)
- Use venv/conda for Python
- Use nvm-windows for Node versions
Tools:
- `where python`, `python --version`
- `where node`, `node -v`, `npm -v`
- `py -0p` (Windows Python launcher)

2.2 Wrong working directory / relative paths
Symptoms:
- Б─°file not foundБ─², Б─°module not foundБ─², config not found
Fix:
- Launch from project root
- Convert relative paths to absolute
Tools:
- Print cwd at boot
- Use Process Explorer to see command line / cwd

2.3 Env vars missing / wrong
Symptoms:
- Б─°KeyErrorБ─², auth failures, wrong ports
Fix:
- Centralize .env
- Validate on boot, fail fast with readable message
Tools:
- `set` (cmd) / `$env:` (PowerShell)
- python-dotenv, dotenv-cli

2.4 Permissions / UAC / protected folders
Symptoms:
- cannot write logs, cannot bind privileged ports, access denied
Fix:
- Move logs to user-writable dir
- Run as proper user, not admin-by-default
Tools:
- Windows Event Viewer (Security)
- ProcMon Б─°ACCESS DENIEDБ─² filters

2.5 Encoding / locale issues (Windows classic)
Symptoms:
- crash when writing Unicode to cp1252 console/log
Fixes:
- Force UTF-8: `PYTHONUTF8=1`, `chcp 65001`, open(log, encoding="utf-8")
- Avoid fancy banners in early boot
Tools:
- Exception traceback
- Minimal reproduction

====================================================================
3) CRASHES (STARTS THEN EXITS)
====================================================================
3.1 Unhandled exceptions
Symptoms:
- exits immediately, no port open
Fix:
- Run in foreground, capture stderr
- Add top-level exception handler + structured logging
Tools:
- `python -X faulthandler`
- Node: `node --trace-uncaught`
- Windows: Event Viewer Application logs

3.2 Native dependency crashes
Examples:
- DLL missing (VCRuntime), OpenSSL mismatch, GPU libs
Fix:
- Install VC++ redistributables
- Pin versions
Tools:
- Dependency Walker (legacy), modern: lucasg/Dependencies
- ProcMon Б─°NAME NOT FOUNDБ─² on DLL loads

3.3 OOM / memory spikes
Symptoms:
- process killed, Windows: Б─°out of memoryБ─²
Fix:
- Increase memory, reduce model sizes, stream data, cap concurrency
Tools:
- Task Manager, Resource Monitor
- `Get-Process | select PM, WS`
- Windows Performance Monitor

3.4 Watchdog restarts / supervisor loops
Symptoms:
- restarts repeatedly, log spam, port flapping
Fix:
- Add backoff, stop restart storms, make crash reason visible
Tools:
- NSSM logs, systemd journal, PM2 logs

====================================================================
4) PORT / LISTEN FAILURES (RUNNING BUT UNREACHABLE)
====================================================================
4.1 Port already in use
Symptoms:
- Б─°Address already in useБ─², or binds to different port silently
Fix:
- Find process using port and stop it, or change port
Tools:
- `netstat -ano | findstr :9999`
- `Get-NetTCPConnection -LocalPort 9999`
- `tasklist /fi "PID eq 1234"`
- Sysinternals TCPView

4.2 Binding wrong interface
Symptoms:
- works on one machine but not another; localhost only
Fix:
- Bind 0.0.0.0 for LAN access, 127.0.0.1 for local only
Tools:
- Inspect server bind config
- `curl http://127.0.0.1:PORT/health`
- `curl http://localhost:PORT/health`

4.3 Firewall / security software
Symptoms:
- port open but connections reset/time out from browser
Fix:
- Add firewall rule, allow app, disable conflicting proxy
Tools:
- Windows Defender Firewall UI
- `netsh advfirewall firewall show rule name=all`

4.4 Proxy / corporate networking
Symptoms:
- browser routes localhost through proxy; websockets fail
Fix:
- Add localhost to proxy bypass
Tools:
- Browser proxy settings, env vars HTTP(S)_PROXY

====================================================================
5) REQUEST FAILURES (SERVER RUNS, BUT RETURNS ERRORS)
====================================================================
5.1 Misconfigured routes / base paths
Symptoms:
- 404s, wrong static directory
Fix:
- Print routing table on startup
- Validate static file root exists
Tools:
- server debug mode
- request logs with path and status

5.2 Auth failures / missing secrets
Symptoms:
- 401/403, Б─°invalid keyБ─², Б─°unauthorizedБ─²
Fix:
- Environment validation on boot; rotate leaked keys
Tools:
- Redact keys in logs
- Use secret stores where possible

5.3 CORS issues
Symptoms:
- browser blocks request despite server ok
Fix:
- Set proper CORS headers; align origin/port
Tools:
- Browser DevTools Network + Console
- curl vs browser compare

5.4 WebSocket handshake failures
Symptoms:
- WS closes immediately; 101 not returned
Fix:
- Ensure correct URL ws:// vs wss://
- Ensure reverse proxy supports websockets
Tools:
- Browser WS inspector
- `wscat -c ws://localhost:9998/ws`

====================================================================
6) DEGRADATION FAILURES (WORKS THEN DIES)
====================================================================
6.1 Memory leaks
Symptoms:
- RAM climbs until crash
Fix:
- profile allocations, cap caches, restart schedule
Tools:
- Python: tracemalloc, objgraph
- Node: heap snapshots, clinic.js
- Prometheus/Grafana

6.2 Handle / fd leaks
Symptoms:
- Б─°too many open filesБ─², Windows handle exhaustion
Fix:
- ensure file/socket close; use context managers
Tools:
- Process Explorer Handles tab
- `lsof` on Linux

6.3 Deadlocks / event loop stalls
Symptoms:
- no crash, but requests hang
Fix:
- timeouts, lock ordering, avoid blocking calls in async loop
Tools:
- Python faulthandler dump
- Node async hooks, `--inspect`
- thread dumps

6.4 CPU saturation & thundering herd
Symptoms:
- latency skyrockets, 503s
Fix:
- queueing, rate limiting, caching, load shedding
Tools:
- perf counters, flamegraphs
- nginx/HAProxy stats

6.5 Disk full / slow I/O
Symptoms:
- writes fail, DB corruption, slow responses
Fix:
- free disk, move logs, rotate, SSD health check
Tools:
- Resource Monitor disk queue
- Windows Event Viewer Disk warnings

====================================================================
7) CONFIG FAILURES (THE SILENT KILLER)
====================================================================
7.1 Wrong config loaded
Symptoms:
- starts with defaults, ignoring your port
Fix:
- log config file path and checksum on boot
Tools:
- print config summary at startup (redacting secrets)

7.2 YAML/JSON parse errors
Symptoms:
- fails immediately; or uses fallback config
Fix:
- validate schema; strict mode
Tools:
- jsonschema, pydantic, zod, ajv

7.3 Version skew
Symptoms:
- after update, endpoints changed
Fix:
- pin versions; lockfiles; semantic versioning
Tools:
- pip freeze, package-lock.json

====================================================================
8) DEPENDENCY FAILURES (PACKAGE CHAOS)
====================================================================
8.1 Missing wheels / compile errors (Windows common)
Symptoms:
- pip stuck, build tools missing
Fix:
- install Build Tools, use prebuilt wheels, pin versions
Tools:
- Visual Studio Build Tools, `pip -v`
- `pip install --only-binary=:all:`

8.2 Conflicting versions
Symptoms:
- import errors, subtle runtime breaks
Fix:
- clean venv; lock dependencies; `pip-tools` / Poetry
Tools:
- `pip check`, `pipdeptree`

8.3 Node global vs local installs
Symptoms:
- Б─°command not foundБ─² or wrong version used
Fix:
- prefer local devDependencies; or ensure global PATH
Tools:
- `where openclaw`, `npm prefix -g`

====================================================================
9) NETWORK / TLS FAILURES
====================================================================
9.1 TLS cert mismatch
Symptoms:
- Б─°NET::ERR_CERTБ─╕Б─², handshake fail
Fix:
- correct certs; trust store; use http for localhost unless needed
Tools:
- openssl s_client, browser cert viewer

9.2 DNS oddities
Symptoms:
- localhost resolves weird via hosts/proxy
Fix:
- check hosts file
Tools:
- `ipconfig /displaydns`, `nslookup`

9.3 Clock skew
Symptoms:
- auth tokens invalid; TLS fails
Fix:
- sync time
Tools:
- Windows Time settings; `w32tm /query /status`

====================================================================
10) DATABASE / STATE FAILURES
====================================================================
10.1 DB connection pool exhaustion
Symptoms:
- slow then 500
Fix:
- pool sizing, timeouts, backpressure
Tools:
- DB logs, slow query logs

10.2 Locked state files
Symptoms:
- Б─°resource busyБ─², cannot open sqlite
Fix:
- ensure single writer; use WAL mode
Tools:
- lsof/handle check

====================================================================
11) OBSERVABILITY: HOW PEOPLE FIX THE Б─°NO LOGSБ─² PROBLEM
====================================================================
The fastest fixes come from making failure visible.

Common patterns:
Б─╒ Boot banner includes:
  - version
  - config path
  - ports
  - dependencies OK
  - health endpoint URL
Б─╒ Always write logs in UTF-8
Б─╒ Log to both console + file
Б─╒ Rotate logs (size + count)
Б─╒ Add /health and /ready endpoints
Б─╒ Add Б─°port checkБ─² after boot and fail if not listening
Б─╒ Create a single Б─°statusБ─² page in the dashboard showing green/yellow/red

Tools people use:
Windows:
- Event Viewer (Application/System)
- Sysinternals: Process Explorer, ProcMon, TCPView, Autoruns
- Resource Monitor / PerfMon
- Windows Firewall logs
- Reliability Monitor

Cross-platform:
- curl / wget for health checks
- Wireshark for network issues
- Postman/Insomnia for API tests
- k6/hey/wrk for load
- Docker logs / compose logs
- Grafana + Prometheus (metrics)
